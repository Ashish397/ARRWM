The move did not change the computation

Against the shipped fleet CSV, 124 of these 130 rows are identical and six differ by 1–7 inliers. All six sit at counts of 12–22, far below the threshold of 50, so no relocation flag and no reported percentage changes. That is the instrument's own RANSAC jitter at marginal match counts, and both trees show it equally.

What the validation turned up

  • The paper's tables are correct. Both columns traced so far reproduce to the digit, from result files dated 2026-08-01 — the current generation.
  • A superseded artefact was nearly shipped. An older relocation file held rows computed against rollouts that had since been re-rendered, because the scan resumes by skipping pairs already present. It does not feed any reported number, and it and its producer are no longer in the release.
  • The instruments now shipped are the ones the paper used — scene_consensus.py for relocation, not the single-reference scan that wrote the stale file. The first version of this validation tested the scan that was subsequently removed; it has been redone against what actually ships.

Standing hazard. Several scans append and skip any (scene, model) already in their output. If a rollout is re-rendered after its row was written, the row is never recomputed and the file silently mixes generations. Delete the output before rescanning whenever an input video has changed.

Reproducing this

AF_FLEET_DIR=<grids> pytest tests/ — the whole suite. Tests needing rollout videos skip cleanly without them. Raw outputs behind this page are in validation/results/: the pytest log, the two A/B runs, the full 2,048-row relocation recomputation, and the recomputed paper tables.
